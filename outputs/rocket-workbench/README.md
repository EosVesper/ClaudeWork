# 火箭发动机热力计算工作台

这是面向课程演示的 Windows 本地应用。界面通过本机 HTTP 服务调用 C/C++ 求解器，包含自带的九系数热力数据库、输运数据库、CoolProp 运行库和已编译的 x64 求解器。

## 启动与数据导出

1. 在安装了 Node.js 20 或以上版本的 Windows x64 电脑上，双击 `Start-Workbench.cmd`。浏览器会在服务就绪后打开 `http://127.0.0.1:8732/`。也可以在项目目录运行 `npm start`。
2. 选发动机预设或固体配方。表单的压强以 MPa 和 kPa 输入，服务统一换算为 Pa。液体工况的主推力室流量可填 0，界面会将绝对推力与尺寸显示为缺失。
3. 「运行计算」计算当前模型；「计算工况区间」再补算冻结流，得到理想热力区间。在高级设置里填写热损失上限后，还会额外计算热损失中点和边界。图谱页的彩色剖面可切换到「相对平衡流差值」；压强和密度使用对数色标。三维扩张段是按面积比旋转、沿对数压强排布的示意体，不是真实型面。
4. 图表可导出 PNG，剖面、收敛过程、区间工况和对比数据可导出 CSV。完整 JSON 包含输入、原始 C 输出、逐次试算、数值检查与公开数据比对。计算输入和结果留在本机。关闭启动窗口可停止服务。

## 验证口径（分三层）

1. **理想热力区间**：同一推进剂、室压、混合比和面积比下，取化学平衡流（理想上限）与组分冻结流（反应完全冻结的极限）两种膨胀模型。「计算工况区间」默认只增加一个冻结流算例。这一层不含实际损失，公开值通常低于它。
2. **实际性能包络**：在理想解上逐项乘以损失因子。交付真空比冲 = η_c* · λ · η_BL · 理想真空比冲，给定环境比冲再扣除按交付 c* 换算的背压项。名义值取平衡流 × 名义因子；下限取冻结流 × 各因子最不利值；上限取平衡流 × 各因子最有利值。燃气发生器循环可切换为整机口径：比冲乘以 1 − (ṁ_GG/ṁ)(1 − c_GG/c)，输入流量视为主推力室流量。因子在「区间与验证」页直接编辑，即时重算，不重新调用求解器。
3. **公开值对照**：公开值与同一层级（整机或推力室）的名义值和包络比较。页面同时给出「所需综合效率」（公开比冲 ÷ 理想比冲），以及「公开推力 ÷ 公开比冲」隐含的总流量，用来判断推力对比是否独立。

默认损失因子及依据：

| 因子 | 下限 / 名义 / 上限 | 依据 |
| --- | --- | --- |
| 燃烧效率 η_c* | 0.96 / 0.98 / 0.995 | [RocketIsp 效率文档](https://rocketisp.readthedocs.io/en/latest/efficiencies.html)：燃烧室综合效率约 98% 为常见值 |
| 喷管出口半角 α_e（λ = (1 + cos α)/2） | 8° / 10° / 15° | Malina 修正；15° 锥形喷管 λ = 0.983 |
| 边界层与摩擦 η_BL | 0.985 / 0.99 / 0.995 | 摩擦效率约 0.99；[RocketIsp 喷管效率（SP-8120 关联式）](https://rocketisp.readthedocs.io/en/latest/nozzle_eff.html) |
| 燃气发生器流量份额 ṁ_GG/ṁ | 0.02 / 0.03 / 0.05 | 课程假设，需用发动机资料覆盖 |
| 涡轮排气速度比 c_GG/c | 0.30 / 0.45 / 0.65 | [MIT 16.512 第 25 讲](https://ocw.mit.edu/courses/16-512-rocket-propulsion-fall-2005/8b2220397190eb677d156c4b486dd069_lecture_25.pdf)：δI/I ≈ (ṁ_GG/ṁ)(1 − c_GG/c)，F-1 算例约 1.1% |

壁面热损失 Q 改为可选的敏感性输入，默认 0：再生冷却发动机的壁面热流大部分回到推进剂，不宜整体计为损失。

其他检查：

- **独立代码复核**：`tools/cantera_crosscheck.py` 用 Cantera 3.2 独立求解三组预设。燃烧室温度、c*、比冲与 C 求解器相差不超过 0.2%，页面「独立代码复核」节逐项列出。
- **数值校核**：燃烧室焓、质量闭合、截面总焓、推力复算可以失败，是真正的校核。熵偏差和喉部声速条件由求解器直接施加，标为「按构造满足」，不作为独立检验。

## 复现与重新编译

- `npm test` 会调用真实求解器，检查三组课设预设的平衡/冻结边界、守恒、收敛、Cantera 复核偏差、损失包络的有序性和公开值判定，也覆盖热损失扫描、固体算例及缺失流量。
- **在 Linux/macOS 上运行**：求解器是 Windows x64 程序。安装 [WineHQ](https://wiki.winehq.org/Download) 后，`npm start` / `npm test` 会自动通过 `wine` 调用（可用环境变量 `ROCKET_WINE` 指定启动器）。云端复核时使用 WineHQ 11.0，结果与 Windows 实算 JSON 逐位一致。注意：Ubuntu 24.04 自带的 Wine 9.0 包启动即崩溃，请使用 WineHQ 官方包。
- `node tools/build-replay.mjs <输出.html> reference-data` 会重新调用求解器，生成离线回放页和 `reference-data/` 实算 JSON。
- `tools/cantera_crosscheck.py` 需要 `pip install cantera`。
- `solver\build-msvc.cmd` 可用已安装的 Visual Studio C++ x64 工具重建带逐次试算输出的求解器。原 MinGW 构建方法见 [求解器说明](solver/README.md)。
- 被调用的求解器使用 `--trace` 导出实际能量方程试算，`--list-engine-data` 导出预设。原有数值方法与工况预设沿用课程工程。
